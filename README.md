# Денталь профи — страница «Почему необходимо КТ»

Одна страница для пациента стоматологической клиники «Денталь профи», который был на консультации,
получил направление на компьютерную томографию (КТ), но через 5–7 дней ещё её не прошёл.
Координатор отправляет ему ссылку в мессенджере. Страница спокойно объясняет, зачем врач назначил
исследование, как КТ помогает спланировать лечение, что важно знать о лучевой нагрузке, как пройти
исследование в диагностическом центре «Пикассо» и что будет после.

Основной вид — телефон; на планшете и компьютере раскладка шире. На странице нет меню, кнопок, ссылок,
видео и всплывающих окон: вопросы пациент задаёт координатору в той же переписке.

Опубликованная версия: https://dashboarddp2013-web.github.io/Pochemu-neobhodimo-kt/

> Перед публикацией тексты должен согласовать врач, а сведения о «Пикассо» (подготовка, время,
> передача результатов) — подтвердить в самом центре.

## Что где лежит

| Путь | Что это |
|---|---|
| `index.html` | вся страница: первый экран и шесть разделов |
| `assets/css/style.css` | стили: цвета, шрифт, раскладка для телефона, планшета и компьютера, анимация |
| `assets/js/main.js` | плавное появление блоков при прокрутке (без JS всё видно сразу) |
| `assets/img/` | картинки: иллюстрации — оптимизированные JPEG в 2× для чётких экранов |
| `assets/img/src/` | исходники — на сайт не публикуются |
| `.github/workflows/pages.yml` | автоматическая публикация на GitHub Pages |
| `tools/` | проверки без браузера (Python 3, только стандартная библиотека) |

Шрифт — **Inter** из Google Fonts (веса 400, 500, 700, 800), подключён одной строкой в `<head>` файла
`index.html`; в `assets/css/style.css` он задан токеном `--font`.

## Как открыть

- **Проще всего:** дважды щёлкнуть по `index.html` — страница откроется в браузере.
- **Как на настоящем сервере:** в папке сайта выполнить `python -m http.server 8780` и открыть
  http://localhost:8780/ (остановить — `Ctrl+C`). Чтобы увидеть страницу как пациент, сузьте окно
  до ширины телефона (360–390 px) — например, в режиме устройства инструментов разработчика (F12).

## Как проверить

Из папки сайта:

```
python tools/check_site.py
python tools/check_assets.py
```

`tools/check_site.py` сверяет страницу с ТЗ: все тексты слово в слово и по порядку, нет старых текстов,
меню, ссылок и кнопок, у картинок есть описание и размеры, файлы на месте и весят вместе не больше 1 МБ,
шрифт Inter, отступы и ряды, бережная анимация. `tools/check_assets.py` проверяет сами картинки.
Код возврата 0 — всё в порядке; иначе печатается список проблем. Если на Windows в выводе кракозябры,
задайте перед командой `PYTHONIOENCODING=utf-8` (в Git Bash: `PYTHONIOENCODING=utf-8 python tools/check_site.py`).

Тексты страницы, которые ожидает проверка, записаны в начале `tools/check_site.py` (`TEXTS`):
если врач поправит формулировку, измените её и в `index.html`, и там.

Пересобрать картинки `assets/img/` (Windows, около 1,5 минуты): `python tools/build_assets.py`,
затем `python tools/check_assets.py`.

## Как опубликовать

Сайт публикуется сам: каждый push в ветку `main` запускает GitHub Actions (вкладка Actions → «Публикация
на GitHub Pages»), через 1–2 минуты новая версия доступна по адресу выше. Наружу уходят только
`index.html`, `.nojekyll` и `assets/` (без `assets/img/src/`); служебные папки и этот README не публикуются.

Если нужно опубликовать в новом репозитории:

1. На github.com: «+» → New repository → имя → Create repository (для бесплатного тарифа — Public).
2. В папке сайта:

   ```
   git remote add origin https://github.com/<логин>/<репозиторий>.git
   git branch -M main
   git push -u origin main
   ```

   При первом push Windows откроет окно входа в GitHub — войдите в браузере.
3. В репозитории: Settings → Pages → Build and deployment → Source: **GitHub Actions**.
4. Дождаться зелёного запуска во вкладке Actions (если он упал до шага 3 — Run workflow).
   Адрес — в Settings → Pages, обычно `https://<логин>.github.io/<репозиторий>/`.
